# Lode

**Lode** — минималистичный, быстрый десктопный Git-клиент для Windows, macOS и Linux на стеке **Tauri 2 + Rust + React 18 + TypeScript + Vite**.

Проект полностью реализован в строгом соответствии с архитектурной спецификацией `CLAUDE.md` (Этапы 0–9).

---

## Архитектура и реализованные возможности (Этапы 0–9)

### 1. Палитра команд (`Ctrl+K` / `Cmd+K`) и горячие клавиши (Этап 9)
- Мгновенный поиск команд с фильтрацией по названию, категории и шорткатам.
- Полная клавиатурная навигация (`▲ / ▼ / Enter / Esc`).
- Быстрый доступ ко всем ключевым действиям:
  - Навигация по вкладкам: История (`Ctrl+1`), Изменения (`Ctrl+2`), Конфликты (`Ctrl+3`), Открытие папки (`Ctrl+O`), Настройки (`Ctrl+,`).
  - Синхронизация: Fetch, Pull, Push, безопасный Push с `--force-with-lease`, управление Remotes.
  - Ветки и теги: Создание веток и тегов, переключение.
  - Индексация: Добавить всё (`Ctrl+Shift+A`), Снять всё, Коммит (`Ctrl+Enter`), Stash.
  - Управление активным состоянием: Продолжить (`--continue`), Отменить (`--abort`).
  - Мгновенное переключение тем: Тёмная, Светлая, Системная.
  - Обновить репозиторий (`F5`), Проверить Git.

### 2. Экран настроек (SettingsModal, Этап 9)
- Постоянное хранение настроек в JSON-конфигурации приложения (`SettingsManager`).
- **Внешний вид**: Переключение темы (system, dark, light), настройка размера шрифта интерфейса (11, 12, 13, 14, 16 px) с динамическим применением CSS-переменных, выбор шрифта UI и моноширинного шрифта кода.
- **Git и поведение**: Настройка режима Pull по умолчанию (`--ff-only`, `--merge`, `--rebase`), выбор и проверка исполняемого файла Git, привязка внешнего редактора (VS Code, Cursor, Sublime Text, Notepad++).
- **Производительность**: Опции включения `core.fsmonitor` и `core.untrackedCache` для гигантских репозиториев (50 000+ файлов).
- **Горячие клавиши**: Наглядная интерактивная памятка клавиатурных комбинаций.
- **О программе**: Версия 0.1.0, стек, лицензия MIT.

### 3. Интерактивный rebase (`rebase -i`, Этап 8)
- Автономный бинарник-редактор (`src-tauri/src/bin/rebase_helper.rs`), вызываемый через `GIT_SEQUENCE_EDITOR` и `GIT_EDITOR` без ненадежных shell-скриптов.
- Модальное окно `InteractiveRebaseModal`: переупорядочивание коммитов (`▲ / ▼`), действия `pick`, `reword` (с диалогом редактирования сообщения коммита), `squash`, `fixup`, `drop`.
- Предупреждение о переписывании опубликованных коммитов по `git rev-list --remotes`.
- Предпросмотр результирующей цепочки коммитов.

### 4. Stash, Cherry-pick, Revert, Reset, Blame (Этап 7)
- Stash: создание с флагом `-u` (`--include-untracked`), список, предпросмотр diff, apply, drop с подтверждением.
- Приёмочный сценарий: конфликт при `stash pop` сохраняет запись в стэше и автоматически открывает редактор конфликтов.
- Cherry-pick с выбором родителя `-m 1/2` для слияний, Revert (`--no-edit`).
- Сброс веток: Soft, Mixed, Hard с подтверждением и интерактивной кнопкой отмены в toast через `git reset --hard ORIG_HEAD`.
- Построчный Blame (`git blame --porcelain`) и история файла с отслеживанием переименований (`git log --follow`).

### 5. Трёхпанельное разрешение конфликтов (Этап 6)
- Парсер маркеров (2-way `<<<<<<< ======= >>>>>>>` и 3-way/diff3 `|||||||`).
- Трёхпанельный редактор с инверсией сторон (ours/theirs) при rebase/cherry-pick.
- Автоматическое объединение идентичных правок, валидация маркеров (защита от сохранения маркеров в файл), атомарная запись с сохранением CRLF и прав доступа.

### 6. Remote и синхронизация (Этап 5)
- Fetch, Pull (ff-only / merge / rebase), Push (`-u`, `--force-with-lease`).
- Определение PushRejected и безопасный force-push с подтверждением для основных веток (`main`, `master`).
- Маскирование логинов и паролей в URL remotes.

### 7. Ветки, теги, merge и определение состояния (Этап 4)
- Парсинг `git for-each-ref`, переключение, ветки, теги, octopus-слияния.
- Определение состояний Merge, Rebase, Cherry-pick, Revert, Bisect по файлам в `.git` через `git rev-parse --git-path`.

### 8. История коммитов и граф веток (Этап 3)
- Парсинг `git log -z`, чистый алгоритм lanes в `src/lib/graph.ts` (8 безопасных цветов, octopus-слияния).
- Виртуализированный рендеринг `@tanstack/react-virtual`, пагинация порциями по 500 коммитов с непрерывными линиями графа.

### 9. Индексация и коммиты (Этап 2)
- Построчный и пофрагментный staging/unstaging, discard с подтверждением, создание коммитов через stdin (`git commit -F -`), валидация темы коммита.

### 10. Статус, diff и файловый вотчер (Этап 1)
- Porcelain v2 статус (`-z --branch`), Inline / Side-by-side diff с лимитами на большие файлы (1 МБ / 5000 строк).
- Файловый вотчер с дебаунсом 200 мс и подавлением собственных событий.

## Требования к окружению

- **Git**: версия 2.30.0 или новее.
- **Node.js**: v18+ или v20+.
- **Rust**: stable toolchain (1.80+).
- **Платформенные зависимости**:
  - **Windows**: WebView2 (встроен в Windows 10/11).
  - **Linux (Ubuntu/Debian)**: `libwebkit2gtk-4.1-dev`, `build-essential`, `libssl-dev`, `libayatana-appindicator3-dev`, `librsvg2-dev`.
  - **macOS**: Xcode Command Line Tools.

## Проверка и тестирование

```bash
# Проверка типов TypeScript (строго без ошибок)
npm run typecheck

# Модульные тесты фронтенда (Vitest: граф, парсер конфликтов, сторы ui, status, refs, remote, conflict, stash, settings)
npm test

# Сборка веб-части
npm run build

# Все тесты Rust (парсеры, conflict markers, stash, blame, rebase, settings, интеграционные тесты Stage 1–9)
cargo test --manifest-path src-tauri/Cargo.toml

# Линтер Rust (строго без предупреждений)
cargo clippy --manifest-path src-tauri/Cargo.toml -- -D warnings
```

## Сборка релизных дистрибутивов

Сборка бандлов для всех платформ:
```bash
# Windows: генерирует MSI и NSIS установщики в src-tauri/target/release/bundle/
npm run tauri build

# CI/CD: настроен GitHub Actions workflow (.github/workflows/release.yml)
# Автоматически собирает, подписывает и прикрепляет к релизу бинарники:
# - Windows: .msi, .exe (NSIS)
# - macOS: .dmg (Universal Binary)
# - Linux: .AppImage, .deb
```

Подробнее об архитектуре криптографических обновлений и подписи релизов см. [docs/UPDATER.md](docs/UPDATER.md).
